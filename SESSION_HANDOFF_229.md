## What happened

1. **Open.** `./baseline.sh --fetch` — one expected red (`repo_check`, the standing unpushed-queue
   drift already flagged at S228 close and unchanged since; the GW-material sub-check inside it
   came back clean, 0 files). Everything else green, 32/33.

2. **Checked the B112/D204 premise before touching anything.** It assumed flipping `enforced: true`
   was safe once Chaos Space Marines shipped (S212/D307). It isn't: read `index.html`'s
   `unlockedAlliedGroups`/`alliedPointsCap` directly — the only engine functions that consume an
   `unlock`-kind effect — and both filter exclusively on `target.allied_group`. The stored effect
   uses `target: {"keyword": "HERETIC ASTARTES"}`, a shape with zero consuming code. Flipping the
   flag today would change nothing at all.

3. **Pulled the actual rule text, not the paraphrase.** `detachments.json`'s `rule_text` and
   `chaos_daemons_reference.md`'s summary both give a generic "Heretic Astartes allies allowed up
   to..." line with no explicit unit list. The real list is in `Detachment_abilities.csv` id
   `000009976` ("Thralls of the First Prince"): 15 named items, 14 literal datasheet names plus
   "Damned units" — itself a Wahapedia keyword group, not a single datasheet.

4. **Resolved "Damned units" against source, not assumption.** `Datasheets_keywords.csv` filtered on
   `keyword == 'Damned'` gives 17 distinct datasheets. Cross-checked all 15 named items plus all 17
   Damned-keyword datasheets against the shipped 58-unit CSM roster: 14 named + 7 Damned-keyword
   units are already built and priced (Wahapedia `source_id 000000012`, CSM's own Codex); the other
   10 Damned-keyword datasheets carry a different, shared source (`000000355`) and have no CSM MFM
   pricing — correctly excluded from the original CSM build for unrelated reasons, not a new gap.
   **21 units buildable total.**

5. **Flagged the over-permissive failure mode explicitly.** A bare "everything with the HERETIC
   ASTARTES keyword" filter would almost certainly sweep in CSM's Epic Heroes and named characters
   (Abaddon, Cypher, Fabius Bile, etc.) — none of which are on the real 21-unit list. Same failure
   shape as B113 (a broad label isn't the real reachable legal set), different mechanism.

6. **Checked for a reusable mechanism before recommending new engine work.** Death Guard's Plague
   Legions and Thousand Sons' Scintillating Legions already solve exactly this rule shape —
   `allied_group`-tagged units, `unlockedAlliedGroups`/`alliedPointsCap`/`canAddUnitToList`/
   `offerableUnits`/E21d stranding all already correct and tested for it. Recommending reuse over a
   second, keyword-based mechanism for one detachment.

7. **Checked one place NOT to blindly copy the precedent.** Plague Legions' ability bans its allied
   units from Warlord; read Shadow Legion's full ability text directly and confirmed it carries no
   such clause. Recommending against adding a matching `warlord` effect — that would invent a
   restriction the source doesn't state.

8. **Wrote it up, did not build.** `B114_SHADOW_LEGION_SCOPE.md` produced. Not a Ryan decision —
   mechanism reuse and a fully source-determined unit set, both "how it gets built" calls under
   standing authority — so B114 stays open, re-scoped, ready to build as its own data-only turn
   whenever picked up, rather than opened for Ryan.
