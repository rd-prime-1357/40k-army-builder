   points, no enhancement cost and no legality test are affected, and assignment eligibility is
   already enforced separately by E4b/B113. It is display fidelity. Corrected in the backlog and
   in D329 so the wrong framing does not propagate.

4. **Three data traps documented before they could ship as bugs.** "Improve" on Armour Penetration
   means *more negative* (`-1` → `-2`) while on S/A/D it means add; `A` and `D` are strings and not
   always numeric, so a variable value composes (`D6` +1 → `D6+1`, a shape already present 99 times
   in the data) rather than computing; and 10 Character/Epic Hero units are loadout-defined with
   more than one model group, where the rollup weapon row spans models the bearer is not — the
   D105/D112 three-way rule applies rather than a written value. Also found two irregular texts
   (*Ancient Weapons*' anaphora, *Blades of Valour* straddling Sets A and D).

5. **Mechanism chosen** (dev-manager call, no Ryan referral): a curated `index.html` table keyed
   `detachment_key + '::' + name` — the exact B113 `ENHANCEMENT_BEARER_RESTRICTIONS` shape and key
   — plus a source-derived census assertion in `rules_assertions.py` that fails on any Set A/A2
   record with no table row. Engine-side text parsing and a parser-emitted `detachments.json` field
   were both considered and rejected; reasons in `B99_SCOPE.md` §5.

6. **Render sites confirmed, no plumbing needed.** `buildWeaponTable` and `loWeaponTable` are
   separate code and both must be fed or the two surfaces will disagree. The configured
   `buildWeaponSections` call already receives `entry`; the unconfigured one correctly does not.
   `loadoutWeaponHtml` already receives `entry`. `entry.enhancement` resolves through the existing
   `enhancementRecord`.

7. **Detachment rule text checked and ruled out.** 31 rule-text sentences carry the same modifier
   shapes, 7 reading as unconditional; all 7 were read directly and every one is an in-battle
   grant or player choice, not an army-construction fact.

8. **Process finding.** Six scope documents are absent from `pipeline_manifest.py`'s GUARDED list

   These are the specs later build sessions read, so an unguarded one can go stale unnoticed.
   Registering six existing files is a tooling change and does not belong in a scoping turn;
   banked as **B121**.
